# 관리자 페이지 구현 계획 (팀 공유용 초안)

2026-10-30, LJS 작성. 같은 날 문서 반영 결정으로 갱신했다. 구현 순서는 팀 합의 전 제안이다.

**담당: 관리자 기능 전부(백엔드 API·관리자 화면)를 LJS가 맡는다.** 관리자 컨트롤러는 규칙상 테이블을 소유한 도메인 패키지에 들어간다(1절). 그래서 다른 담당의 도메인 코드를 고치게 되는 화면이 있다. 2절 표의 "도메인 담당(협의)" 칸이 그 화면에서 미리 이야기할 사람이다.

## 0. 범위와 전제

- 이 문서는 백엔드 관리자 API 계획이다. 관리자 화면(프론트)도 LJS가 프론트 저장소에서 같은 화면 ID로 따로 진행한다.
- 관리자 요구사항은 요구사항정의서 v0.10.0의 REQ-ADM-001~024다(007은 006에 통합). 화면과 기능은 관리자 화면설계서 v0.2, 관리자 기능명세서 v0.3에 있다.
- 이 계획은 DMS 최신 문서와 당시 DB 기준 파일을 대조해 뽑은 관리 항목에, 인터뷰로 정한 결정 33건(부록 A)과 2026-10-30 보완 결정(부록 B)을 반영한 것이다. 지금 기준은 요구사항정의서 v0.10.1, IA 구조도 v0.5, 정책결정관리서 v0.3, 관리자 기능명세서 v0.4, 관리자 화면설계서 v0.3, `db/20261030_create_tables_v0.11.sql`이다.
- 마일스톤은 화면 ID 하나 단위다(`docs/convention/milestone.md`). 화면 ID는 2절의 SCR-ADM 번호를 쓴다. 결번은 재사용하지 않는다.

## 1. 구현 원칙

`docs/convention/architecture.md` "관리자 코드"를 따른다.

| 경우 | 위치 |
|---|---|
| 한 도메인 테이블만 읽거나 바꾼다 | 그 도메인의 `controller/AdminXxxController` |
| 두 도메인 이상을 합쳐 조회만 한다 | `admin` 패키지 |
| 두 도메인 이상인데 데이터를 바꾼다 | 바꾸는 테이블을 소유한 도메인 |
| 도메인을 모르는 공통 기능(감사 로그, 설정, 공통코드, 배치·외부 API 로그) | `global` |

- 경로는 모두 `/api/admin/`으로 시작한다. `SecurityConfig`가 이 경로를 `ROLE_ADMIN`으로 막고 있다(이미 있다).
- 관리자 계정도 `MBR`의 한 행이다(`MBR_AUTHRT_CD = USRC0005`). 계정 관리는 `member`의 `AdminMemberController`에 둔다.
- 관리자 작업은 모두 감사 로그(`MNGR_TASK_LOG`)에 남긴다. 전후 값을 아는 service가 `global/log`의 `AdminTaskLogService`를 명시 호출해 같은 트랜잭션에서 남긴다.
- 알림(신고 결과, 공지, 정지 안내)은 `@Transactional` 안에서 `EventPublisher.publish()`로 발행한다.
- 다른 도메인 기능이 필요하면 낮은 층 service만 부른다. 예: `community`(3층)의 신고 조치가 작성자를 정지하면 `member`(0층) service를 부른다.

### 2단계: 공통 기반

뒤의 관리자 API가 모두 쓰는 것이다.

- 감사 로그 기록 수단과 조회(SCR-ADM-114)
- 배치 실행 이력 기록. 기존 `scheduler`·`health` 배치(`CareMissionJob`, `CareScheduleAlarmJob`, `AiConversationPurgeJob`, `PrescriptionExpiryJob`)에 붙인다(SCR-ADM-111)
- 외부 API 호출 로그. Java 호출은 `global/external` 호출부에 붙이고, Python 호출은 내부 API로 통지받아 남긴다. 통지 실패는 사용자 응답에 영향을 주지 않는다(SCR-ADM-082·112)
- 운영 설정 수정(SCR-ADM-110)
- 관리자 목록 공통 응답 형식(페이징·검색 조건)

### 3단계: 운영 핵심

신고·문의를 처리할 수 없으면 서비스를 운영할 수 없다. 그래서 가장 먼저 한다.

1. 회원 목록·제재·탈퇴 회원(010·012·013), 관리자 계정(113)
2. 회원 상세 조합(011)
3. 게시글·댓글(020), 신고(030)
4. 공지·FAQ·문의(040~042). 문의의 캐릭터 오류 처리는 `pet` service에 둔다

### 4단계: 콘텐츠·마스터

1. 아이템(070), 알림 템플릿·발송 이력(090·091). LJS 도메인이라 협의 없이 바로 할 수 있다
2. 실종·펫돌봄·노출 콘텐츠(021~023), 펫뉴스(050), 품종(101)
3. 약관(051), 장소(060)
4. 케어미션·포인트(071·072)

### 5단계: AI·대시보드

1. 라우팅 매핑표·키워드 사전(080·081). 지금 부록 A·B를 쓰는 코드를 DB에서 읽도록 바꾸는 작업이 같이 들어간다. Python AI 서버는 DB에 붙지 않으므로(2026-10-26 결정) Java가 조회 API로 내려 준다.
2. 처리 현황(082), 대시보드(001). 다른 도메인 집계 service가 다 나온 뒤에 만든다.
