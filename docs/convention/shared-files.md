# 여러 명이 같이 고치는 파일

`ErrorCode`, `application.properties.example`, `db/`의 SQL을 고칠 때 연다.

`ErrorCode`와 `application.properties.example`(실제 `application.properties`는 git 제외, 디스코드로 공유)은 모든 도메인 담당이 줄을 추가한다. 다들 맨 끝에 붙이면 병합할 때마다 충돌한다.

- 파일 안을 도메인별 구획으로 나누고(주석으로 구분), 자기 도메인 구획 안에 추가한다.
- 이 파일들의 줄 정렬이나 순서 바꾸기를 기능 PR에 섞지 않는다.

`db/`의 SQL 파일도 여러 명이 고친다. 2026-10-30부터 마이그레이션 파일을 따로 만들지 않고 기준 파일 두 개만 고친다.

- `db/` 바로 아래에는 지금 버전의 기준 파일 두 개만 둔다: `YYYYMMDD_create_tables_vX.Y.sql`(전체 DROP 후 생성), `YYYYMMDD_insert_base_data_vX.Y.sql`(공통코드·케어미션 마스터). 지난 버전은 `db/archive/vX.Y/`에 있다.
- 테이블과 기준 데이터를 바꿀 때는 두 파일의 본문(CREATE·INSERT)을 직접 고친다. 새 공통코드는 기존 DB와 `COM_CD_SN`이 같도록 공통코드 절 끝에 붙인다.
- 같은 PR에서 그 파일 맨 위 "vX → vY 변경" 절에 기존 DB에 실행할 SQL(ALTER·CREATE·INSERT, 기존 행을 채우는 UPDATE)을 주석으로 적는다. 주석이라 새 DB를 만들 때는 실행되지 않는다. 항목마다 번호, 날짜, 이니셜, 이유와 근거(문서·기능 ID)를 적는다.
- 병합된 변경 절 항목은 고치지 않는다. 이미 공용 DB에 실행됐을 수 있기 때문이다. 바꿀 것이 있으면 새 항목을 추가한다.
- 테이블을 바꾸는 PR은 본문에 "DB 변경 있음"과 변경 절 항목 번호를 적는다.
- PR 작성자가 병합 직후 팀 공용 DB에 그 항목의 SQL만 실행하고 PR에 완료 댓글을 남긴다. 기준 파일 전체는 공용 DB에 실행하지 않는다.
  - 실행할 때 맨 앞에 `SET NAMES utf8mb4;`를 넣는다. DBeaver의 Execute script(`mysql.exe`)는 한국어 윈도우에서 euckr로 접속해서, 이 줄이 없으면 한글 값이 오류(1366·1267)가 난다.
  - 오류가 나면 거기서 멈춘다. DBeaver에서 오류가 나도 계속하는 설정은 끈다. MySQL DDL은 롤백되지 않는다.
- 버전은 사람이 정할 때만 올린다(예: ERD 버전을 올릴 때). 올릴 때는 두 파일을 `db/archive/vX.Y/`로 옮기고, 복사해 새 버전 이름으로 만든다. 변경 절은 비운다. 파일 이름을 가리키는 곳(시드 파일 머리말, `docs/`)도 함께 고친다.

시드 데이터는 `db/seed/`의 SQL 파일 하나다. 기준 파일 위에 실행한다.

- 테이블을 바꾸면 바뀐 테이블에 맞게 시드 파일을 다시 만든다.
